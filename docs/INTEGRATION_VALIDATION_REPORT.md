# تحقق التكامل وجاهزية Staging

التاريخ: 2026-10-28. الفرع: `cursor/erp-finance-inventory-crm`. لم يُدمج `main` ولم يُنشر إنتاج ولم تُطبَّق هجرة على قاعدة مستضافة.

## القرار

**No-Go للإنتاج ولـ Staging المستضاف.** **Go لتجربة محلية من المتصفح حتى قاعدة بيانات على `127.0.0.1` فقط.** المتوسط المتحرك في هذه التجربة خيار تجريبي، والافتراض المخزّن يبقى سعر أمر الشراء.

## ما فحصه التدقيق

مسارات الشراء والبيع الموجودة تستدعي الخدمات الحقيقية. الصفحة الرئيسية `/` تعرض لافتة معاينة بأرقام ثابتة. شاشات `/erp` تنادي `/api/v1`. كل مسار API يمر من `protectedRoute`: يرفض الطلب العابر للموقع، ثم يتحقق من الجلسة والصلاحية. اختبار المصفوفة داخل Vitest يحمّل كل المسارات. لم يُعثر على شاشة تشغيل تستخدم بيانات وهمية غير معلّمة.

جلسة المتصفح ما زالت Supabase. بلا مشروع مستضاف لا توجد جلسة حقيقية. أُضيفت كعكة موقعة تعمل فقط عندما `AETHER_E2E=1` والعملية ليست إنتاجًا و`DATABASE_URL` على `127.0.0.1`. الكعكة تسمي المستخدم. العضوية والصلاحيات تُقرأ من قاعدة البيانات بعد ذلك. إنتاج وStaging يتجاهلانها.

## ما شغّله المتصفح

`npx playwright test` نجح: اختبار واحد في 1.4 دقيقة، على PostgreSQL محلي يحذفه السكربت عند التوقف. Chromium فتح الواجهة.

- العربية ثم الإنجليزية على الصفحة الرئيسية، ثم شاشة المالية باللغتين، مع `dir` الصحيح.
- شاشة الأعضاء تعرض تبويب الصلاحيات. شاشة المشتريات تعرض عنوان الدورة.
- زائر بلا كعكة يُحوَّل إلى تسجيل الدخول، وطلب إنشاء حساب يرجع 401.
- عضو بدور المشاهدة يرجع 403 عند إنشاء حساب.
- استلام 10، إعادة 1، فاتورة مورد لـ 9 بعملة KWD، دفعة جزئية 4.000، تحويل عرض سعر لأربع وحدات، قيد تكلفة بضاعة، تحصيل جزئي 2.000 والحالة `partially_paid`.
- إعادة مفتاح الاستلام نفسه لا تنشئ استلامًا ثانيًا. العد في الجدول صف واحد.
- الشركة الثانية لا ترى الفاتورة، لا في الواجهة ولا في `invoices`.
- بعد الدورة: الكمية 5، المتوسط 1.000، حساب المخزون 5.000، تكلفة البضاعة 4.000، والقيود المرحلة متوازنة.

السكربت `scripts/e2e-local.mjs` يرفض الإقلاع إذا فشل فحص RLS، ويرفض الإقلاع إذا كان `DATABASE_URL` مضبوطًا مسبقًا. وصول المتصفح يعني أن فحص العزل نجح في تلك العملية. لا تُطبع كلمة مرور القاعدة.

## البوابات الأخرى في هذه الجولة

- `npx tsc --noEmit`: نجاح.
- `npx eslint src scripts e2e playwright.config.ts --ext .ts,.tsx,.js,.mjs`: نجاح.
- `npx vitest run --maxWorkers=2`: 1074 اختبارًا نجحت، وفشل فحص واحد لأن اختبار البوابة كتب سلسلة اتصال. أُزيلت السلسلة. إعادة `migration-safety.test.ts` و`e2e-session.test.ts`: 11 اختبارًا نجحت.
- `npm run build`: نجاح. `next-env.d.ts` أُعيد ولم يُحفظ.
- سطر `relation "invoices" does not exist` وتحذيرات العزل وحد المعدل داخل Vitest رفضات متوقعة في اختبارات ناجحة.

## Staging المستضاف

لا بيانات اتصال متاحة لهذه الجولة، ولم تُفتح ملفات البيئة الحقيقية. `.env.example` و`.env.staging.example` يبقيان عناصر نائبة. التعليق في المثال يقول إن `AETHER_E2E` لا يُضبط على Staging أو Production.

التشغيل المستضاف يحتاج، بعد موافقة منفصلة: مشروع Supabase خاص بالتجربة، `DATABASE_URL` له، المفتاح العام، ثم `node scripts/migrate.mjs` على ذلك المشروع فقط. حتى ذلك الحين الأمر المحلي هو `npm run e2e`.

## ما بقي بلا قرار

اعتماد المتوسط للإنتاج، وأوامر البيع، واسترداد فاتورة مدفوعة، وإلغاء مرتجع المشتريات، وموافقة فرق السعر. مسجّلة في `docs/OPEN_ACCOUNTING_DECISIONS.md`.
