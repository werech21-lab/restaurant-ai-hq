# نشر موقع Aether BI

التاريخ: 2026-10-28. المستودع: `werech21-lab/restaurant-ai-hq`. العمل على الفرع `cursor/erp-finance-inventory-crm` فقط. لم يُدمج `main` ولم يُنشر إنتاج.

## أين يُستضاف aetherbi.com

الموقع على Vercel، مشروع `werech21-lab/restaurant-ai-hq-v23` (`prj_xtpiDK6iXstPb90eoTezTFmiiA13`).

| البند | القيمة |
| --- | --- |
| النطاق | `aetherbi.com` و`www.aetherbi.com` على هذا المشروع فقط |
| DNS | المسجّل طرف ثالث. `www` يشير إلى `cname.vercel-dns.com`. القمة `A` إلى `76.76.21.21` |
| خادم الاستجابة | `Vercel`، المنطقة `iad1` |
| الجذر | `.` |
| البناء | أمر Next الافتراضي `npm run build` |
| متغيرات البيئة | لا يوجد أي متغير على Production أو Preview أو Development |
| فرع الإنتاج | `main` |

مشروعا `restaurant-ai-hq` و`restaurant-ai-hq-v2` موجودان في الحساب نفسه ولا يملكان `aetherbi.com`. لم يُمسّا، ولم تُمس مشاريع أخرى.

## لماذا لم تظهر وحدات ERP

الإنتاج آخر نشر له في 25 أكتوبر 2026، من `main`، والاسم المستعار `restaurant-ai-hq-v23-git-main-werech21-lab.vercel.app`. ذلك البناء لا يحتوي إلا الصفحة الرئيسية وصفحة غير الموجود. `main` في Git لا يحتوي مسارات `/erp`.

تطوير ERP على `cursor/erp-finance-inventory-crm`. دفع هذا الفرع ينشئ Preview محميًا بتسجيل دخول Vercel، ولا يغيّر `aetherbi.com`. معاينة سابقة عمرها نحو أربع ساعات كانت تحمل واجهة ERP، وفتحها في المتصفح أعاد التوجيه إلى صفحة دخول Vercel. لذلك نجاح البناء على الفرع لا يعني أن الموقع العام تحدّث.

فحص مباشر لـ `https://www.aetherbi.com/` بعد هذه الخطوة: الصفحة القديمة ما زالت تُخدم، و`/erp` يعيد 404، ولا يوجد مركز التطبيقات.

## ما أصبح جاهزًا للعرض

الصفحة الرئيسية في نسخة التطوير تعرض الآن مركز تطبيقات ERP فوق غرفة القيادة، بالعربية والإنجليزية، مع الإبقاء على تنبيه أن أرقام الغرفة ثابتة وليست بيانات تشغيل. البطاقات تفتح صفحات موجودة:

| الوحدة | المسار |
| --- | --- |
| الفواتير والمدفوعات | `/erp/finance` |
| دفتر الأستاذ | `/erp/ledger` |
| المشتريات والموردون | `/erp/procurement` |
| المخزون والتكلفة | `/erp/inventory` |
| العملاء وعروض الأسعار | `/erp/crm` |
| العلامات والفروع | `/erp/org` |
| الدعوات والصلاحيات | `/erp/iam` |
| التنبيهات والموافقات | `/erp/ai` |

المطبخ والتوصيل والجودة ومجلس الوكلاء تبقى داخل غرفة القيادة البصرية، ومُعلَّمة بأنها ليست تشغيل ERP. لا بيانات تجريبية تُعرض كتشغيل.

## معاينة منشورة

الرابط: https://restaurant-ai-hq-v23-6agcxy2gj-werech21-lab.vercel.app

الحالة `READY`. الهدف ليس إنتاجًا (`productionUrl` فارغ). `aetherbi.com` لم يتغير.

المعاينة محمية بـ `vercel_authentication`، فالمتصفح بلا جلسة الفريق يصل إلى صفحة دخول Vercel. التحقق تم بأمر `vercel curl` الخاص بالحساب:

- الصفحة الرئيسية تحتوي مركز التطبيقات والتنبيه العربي وروابط `/erp/finance` و`/erp/ledger` و`/erp/org` و`/erp/iam`.
- `GET /erp/finance` يعيد `307` إلى `/login?next=%2Ferp%2Ffinance`.

محليًا على `127.0.0.1:4020`: المركز ظاهر بالعربية ثم بالإنجليزية، و`/erp/finance` يفتح شاشة الدخول التي تقول إن Supabase غير مربوط. لا مفاتيح في المتصفح لأن المشروع بلا متغيرات عامة.

## العوائق

- الإنتاج ما زال `main`. إظهار ERP على `aetherbi.com` يحتاج نشر إنتاج صريحًا، وليس دفع فرع التطوير.
- لا `DATABASE_URL` ولا مفاتيح Supabase على Vercel. تسجيل الدخول والوحدات لن تعمل ببيانات حتى تُضبط بيئة خاصة بالإنتاج. لا يُربط الموقع العام بقاعدة Staging.
- ترحيلات Staging ما زالت NO-GO حتى استعادة النسخة وموافقة صريحة.
- حماية المعاينة تمنع الزائر العام من فتح رابط Preview بلا عضوية الفريق.

## خطوات النشر النهائي

لا تُنفَّذ قبل موافقة صريحة:

1. الإبقاء على `.env.staging` خارج Git وخارج Vercel.
2. إنشاء قاعدة إنتاج منفصلة، أو قرار مكتوب بخلاف ذلك. ثم ضبط `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` و`DATABASE_URL` و`DATABASE_SSL=verify` مع الشهادة العامة على بيئة Production فقط.
3. أخذ نسخة قابلة للاستعادة ثم تطبيق `0001`–`0017` على تلك القاعدة، لا على Staging الحالي إلا بموافقة مستقلة.
4. دمج `cursor/erp-finance-inventory-crm` إلى `main` بموافقة، لأن فرع الإنتاج هو `main`. البديل هو تغيير فرع الإنتاج في إعدادات Vercel، وهو أيضًا قرار إنتاج.
5. بعد الدمج، التأكد أن النشر الجديد يحمل اسم `git-main` وأن `https://www.aetherbi.com/` يحتوي `erp-apps` وأن `/erp` لم يعد 404.
6. الأمر `vercel deploy --prod` لم يُشغَّل، ولا يُشغَّل قبل الخطوات السابقة.
