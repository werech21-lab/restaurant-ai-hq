# نتائج الاختبار الشامل — Aether BI

التاريخ: 2026-10-28. كل الأرقام من هذه الجلسة. لا شيء منها على المشروع المستضاف.

## الأرقام

| الفحص | النتيجة |
| --- | --- |
| TypeScript | خروج 0 |
| ESLint | خروج 0 |
| Vitest | 58 ملفًا، **1081** اختبارًا ناجحًا، 209.22 ثانية |
| البناء | خروج 0، تجميع 34.8 ثانية |
| Playwright، التشغيل الأول | 7 ناجحة و1 فشل: مهلة 180 ثانية بينما قائمة الفواتير ما زالت «جارٍ التحميل…» بعد إقلاع بارد |
| Playwright، إعادة دورة الشراء والبيع | **1** ناجحة، 2.0 دقيقة |

سطر `relation "invoices" does not exist` وتحذيرات رفض الطلب العابر وحد المعدل ظهرت داخل اختبارات الأمان الناجحة.

## الدورة التي نجحت في الإعادة

على Postgres محلي جديد، عبر المتصفح و`/api/v1` ثم جزم SQL:

- عربي وإنجليزي واتجاه الصفحة.
- شركة ومالك ومشاهد من الإقلاع.
- طلب شراء وأمر واستلام، ثم إعادة مفتاح الاستلام بلا صف ثانٍ.
- مرتجع، فاتورة مورد، وسداد جزئي.
- عرض سعر ثم إرسال وقبول وتحويل إلى فاتورة بيع بعملة KWD وإجمالي 6000 فلس وقيد تكلفة بضاعة.
- تحصيل جزئي والحالة `partially_paid`.
- رقم الفاتورة ظاهر في شاشة المالية.
- الشركة الثانية لا ترى الفاتورة (404) ولا صفها.
- المخزون 5، والمتوسط 1000، ورصيد حساب المخزون 5000، وتكلفة البضاعة 4000.
- القيود المرحلة المتوازنة: صفر قيد غير متوازن.
- مورد واحد وإيصال استلام واحد.

## حالات الفشل التي نجحت في التشغيل الأول

- جلسة تالفة.
- تجاوز صلاحية المشاهد.
- ترويسة مؤسسة أخرى.
- تكرار الطلب بجسم مختلف.
- بيع بمخزون غير كافٍ.
- قيد غير متوازن.
- قطع الاتصال أثناء معاملة مفتوحة.

التزامن وإصدارات الصفوف وأقفال المخزون داخل ملفات قاعدة Vitest التي دخلت في الـ 1081 الناجحة.

## ما لا تثبته هذه النتائج

PGlite و`127.0.0.1` ليسا إثباتًا لمشروع `aether-bi-staging`. RLS المستضاف، وجلسة Auth الحقيقية، وتطبيق `0001`–`0017` على القاعدة المستضافة لم تُشغَّل.
