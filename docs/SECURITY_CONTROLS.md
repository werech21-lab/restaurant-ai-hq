# ضوابط الحماية في طبقة الـ API

كل مسار تحت `/api/v1/**` يمرّ عبر `protectedRoute` أو `sessionRoute` في `src/lib/api/route.ts`. أُضيف إلى هذا الغلاف حارسان، فلا يحتاج أي ملف route إلى تعديل.

## 1. منع الطلبات من مواقع أخرى (CSRF)

المصدر: `src/lib/http-origin.ts`.

- يسري على `POST` و`PUT` و`PATCH` و`DELETE` فقط.
- يُقبل الطلب إذا كان `Sec-Fetch-Site` يساوي `same-origin` أو `none`، وكان `Origin` — إن وُجد — على مضيف التطبيق نفسه (`Host` أو المضيف الذي حلّه الإطار).
- يُرفض بـ **403** والرمز `cross_site_forbidden` في الحالات: `Sec-Fetch-Site` يساوي `cross-site` أو `same-site`، أو `Origin` على مضيف آخر (ومنه منفذ مختلف أو مضيف يشبه مضيفنا)، أو `Origin` غير قابل للقراءة مثل `null`.
- الرفض يسبق التحقق من الهوية، فالطلب المزوَّر لا يكلّف استعلامًا واحدًا على قاعدة البيانات.
- الطلب الذي لا يحمل أيًّا من الرأسين يُقبل: ليس طلب متصفح (خادم آخر، `curl`، اختبار)، ولا يمكنه حمل كوكي جلسة شخص آخر، ويظل محكومًا بالمصادقة وRBAC.

## 2. تحديد معدل الطلبات

المصدر: `src/lib/rate-limit.ts`. نافذة ثابتة طولها دقيقة، والساعة مُحقَنة فالسلوك قابل للاختبار بدقة.

- المفتاح: الشركة + المستخدم + مجموعة المسار (`finance/invoices` مثلًا، فالمسارات الفرعية تتقاسم الميزانية نفسها). لا تدخل معرّفات السجلات في المفتاح.
- السقف: **240** قراءة و**60** كتابة لكل مفتاح في الدقيقة. الميزانيتان منفصلتان.
- التجاوز يُردّ بـ **429**، بالجسم `{ error: { code: 'rate_limited', message, details } }` ورأس `Retry-After` بالثواني. الطلب المرفوض لا يُحتسب، فلا يمدّ النافذة.
- العدّ يبدأ بعد نجاح المصادقة، لأن المفتاح يحتاج هوية المستخدم وشركته.
- الذاكرة محدودة: 20٬000 نافذة حيّة كحد أقصى، تُحذف المنتهية أولًا ثم الأقدم.

## 3. ما **لا** تحميه هذه الإضافة

- **النشر متعدد النسخ:** العدّاد في ذاكرة عملية Node واحدة. نسختان خلف موازن حِمل تعنيان ضِعف السقف فعليًا، وإعادة التشغيل تنسى كل النوافذ. الحماية الحقيقية لنشر متعدد النسخ تحتاج مخزنًا مشتركًا أو محدِّدًا عند الحافة، وهو قرار نشر لم يُتَّخذ هنا عمدًا: لم تُضَف أي تبعية ولا Redis ولا طابور.
- **فيضان غير مُصادَق:** طلبات بلا جلسة لا تُحتسب، لأن المفتاح لا يكتمل. تُردّ بـ 401 من المصادقة، لكن كلفة كل طلب (استدعاء Supabase) تبقى قائمة. حمايتها مكان الحافة أو الوكيل العكسي.
- **تسجيل الدخول والـ Server Actions:** مسارات Supabase و`src/app/**` لا تمرّ بهذا الغلاف، فلا سقف عليها ولا فحص مصدر. فحص المصدر الخاص بـ Server Actions هو فحص Next.js المدمج وحده.
- **القراءات عبر المواقع:** مسموحة في الحارس؛ ما يمنع قراءة الجسم هو غياب رؤوس CORS لا هذا الفحص.
- **مخطط الـ Origin:** تُقارَن أسماء المضيفين فقط لا البروتوكول، فصفحة على `http` بالمضيف نفسه تُعدّ من أصلنا.
- **خلف وكيل عكسي:** المضيف المقبول يأتي من رأس `Host` أو ممّا حلّه الإطار من المضيف المُمرَّر. وكيل يُمرّر مضيفًا خاطئًا يكسر الفحص.
