# حالة الربط المستضاف — Aether BI

التاريخ: 2026-10-28. الفرع: `cursor/erp-finance-inventory-crm`.

**العائق الحقيقي: `DATABASE_URL` غير موجودة في `.env.staging`.** لم يُنفَّذ استعلام على القاعدة المستضافة، لذلك الاتصال غير مثبت.

## ما تم التحقق منه

| البند | النتيجة |
| --- | --- |
| الملف | `restaurant-ai-hqw/.env.staging` موجود |
| Git | `.gitignore` يستبعد `.env.staging` |
| المفاتيح الموجودة | عنوان المشروع، المفتاح القابل للنشر، `DATABASE_SSL=verify` |
| `DATABASE_URL` | غير موجودة |
| مجمع الجلسة | `aws-0-ap-southeast-1.pooler.supabase.com` يُحل |
| المشروع الحي | `aether-bi-staging` / `pikqnlzkoaxoxpahztvc` / `ACTIVE_HEALTHY` |
| المستخدم والمنفذ والقاعدة | `postgres.pikqnlzkoaxoxpahztvc`، `5432`، `postgres` |

لوحة المشروع أظهرت كلمة المرور الجديدة مرة واحدة. نسخها إلى الملف لم يكتمل قبل أن تتغير الشاشة. لم تُطبع السلسلة ولم تُحفظ في Git.

مربع إدخال محلي بعنوان `Aether BI staging` مفتوح على سطح المكتب. الحقل مخفي. الحفظ يرفض أي مضيف أو مستخدم غير المشروع أعلاه، ويرفض كلمة مرور فيها `@` غير مرمّزة `%40`.

## ما لم يُنفَّذ

لا فحص `current_database()` ولا `current_user`. لا جرد جداول ولا `schema_migrations`. لا نسخة احتياطية. لا ترحيل. لا إعادة لتشغيل Vitest أو Playwright في هذه الخطوة، لأن الشجرة لم تتغير منذ نجاح 1081 اختبارًا و8 اختبارات متصفح في اليوم نفسه.

## الحكم

**NO-GO** لأي كتابة على القاعدة المستضافة. بعد حفظ السلسلة في المربع، الخطوة التالية هي اتصال قراءة فقط مع التحقق من الشهادة، ثم تقرير الترحيلات، ثم التوقف حتى توجد نسخة قابلة للاستعادة وموافقة صريحة.
