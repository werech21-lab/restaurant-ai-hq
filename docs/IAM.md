# الدعوات وإدارة الأدوار داخل المؤسسة

الحالة: **الخلفية (API + قاعدة البيانات + اختبارات) منفَّذة. الواجهة غير مبنية.** الترحيل `0010_iam.sql` مكتوب ومختبر ومُطبَّق فقط على قواعد PGlite المؤقتة، ولم يُطبَّق على أي قاعدة حقيقية.

الشيفرة في `src/lib/iam/` (بنية مشتركة، وليست وحدة من الخمس. انظر «انحراف» في `docs/EVENT_DESIGN.md`).

## 1. المبدأ: لا صلاحية إدارية تُمنح تلقائياً

1. **لا دور افتراضي.** `roleId` حقل إلزامي في الدعوة ولا يوجد fallback.
2. **الصلاحيات الإدارية هي عائلة `iam.*`** (`iam.member.read|invite|update|remove`, `iam.role.read|manage`). تُمنح بالترحيل لدور `owner` فقط (دور النظام). لا `accountant` ولا `approver` ولا `viewer`.
3. **قاعدة السقف** (`checkGrant`): لا أحد يمنح دوراً فيه صلاحية لا يملكها هو نفسه، بدعوة أو تغيير دور أو كتابة دور.
4. **الدور الإداري** (فيه أي `iam.*`) لا يمنحه إلا حامل `iam.role.manage`، حتى لو كان المانح يملك كل صلاحياته. من يملك `iam.member.invite` فقط لا يصنع إداريين.
5. **إدارة الإداريين:** تغيير دور عضو إداري أو إزالته تتطلب `iam.role.manage`.
6. **المستخدم لا يغيّر دور نفسه ولا يزيل نفسه.**
7. **آخر مدير:** أي عملية (تغيير دور، إزالة، تعديل دور) تُبقي المؤسسة بلا حامل لـ `iam.role.manage` تُرفض بـ 409 `last_admin` ويُتراجع عنها.
8. **أدوار النظام الأربعة** (`owner, accountant, approver, viewer`) مقفلة للتعديل (403 `system_role_locked`). تُنشأ أدوار مخصصة بدلاً من ذلك.

## 2. أمان الدعوة

| الخاصية | التنفيذ |
| --- | --- |
| الرمز | 256 بت عشوائي (`randomBytes(32)`, base64url)، يظهر **مرة واحدة** في رد الإنشاء مع `Cache-Control: no-store` |
| التخزين | SHA-256 فقط (`token_hash`). الرمز نفسه لا يُخزَّن ولا يُسجَّل ولا يدخل التدقيق ولا الأحداث |
| قراءة `token_hash` | ممنوعة عن `anon` و`authenticated` بمنح أعمدة (column grants)، حتى للمالك (مختبر) |
| الإرسال | **لا يُرسَل شيء.** صاحب الدعوة يسلّم الرابط بنفسه (لا مزوّد بريد مُعتمد بعد) |
| الصلاحية | افتراضياً 7 أيام، الحد الأقصى 30. `pending` بعد الانتهاء تُقرأ `expired` (بلا مجدول) |
| الوحدانية | دعوة معلّقة واحدة لكل (مؤسسة، بريد) بفهرس جزئي فريد. المنتهية تُغلق وتُدقَّق عند إنشاء جديدة |
| القبول | يتطلب جلسة، وبريداً **مؤكَّداً** يطابق بريد الدعوة. أي سبب فشل (رمز خاطئ، بريد مختلف، منتهية، ملغاة، مستخدمة، مؤسسة معلّقة، المُدعي غادر أو فقد صلاحية منح الدور) يعطي **نفس الرد 404** `invitation_invalid` |
| حالة نهائية | `accepted` و`revoked` نهائيتان، ويحرس ذلك trigger في قاعدة البيانات، كما لا يُغيَّر المستأجر/البريد/الدور/الرمز/المُنشئ |
| التزامن | قفل المؤسسة ثم الدعوة بالترتيب نفسه في كل كاتب. `version` على الإلغاء |

القبول يتحقق أيضاً من أن **المُدعي ما زال عضواً ويملك الآن صلاحية منح الدور**؛ دعوة أصدرها شخص خُفِّضت صلاحيته أو غادر لا تنفع.

## 3. المسارات (`/api/v1/iam/...`)

| الطريقة والمسار | الصلاحية |
| --- | --- |
| `GET members` | `iam.member.read` |
| `PATCH members/{userId}` `{roleId, expectedRoleId}` | `iam.member.update` |
| `DELETE members/{userId}?expectedRoleId=` | `iam.member.remove` |
| `GET roles` · `POST roles` · `PATCH roles/{id}` | `iam.role.read` · `iam.role.manage` · `iam.role.manage` |
| `GET invitations?status=` · `POST invitations` | `iam.member.read` · `iam.member.invite` |
| `POST invitations/{id}/revoke` `{version}` | `iam.member.invite` |
| `POST invitations/accept` `{token}` | **جلسة فقط** (لا مؤسسة بعد). الاستثناء الوحيد من قاعدة «كل مسار يفحص صلاحية RBAC»، موثَّق ومختبر في مصفوفة الوصول |

كل الخدمات تفحص الصلاحية أيضاً داخل الخدمة (دفاع مزدوج)، وتُرمى 409 `version_conflict` عند التعارض، وتُكتب صفوف تدقيق (`entity`: `invitation|member|role`)، وتُنشر الأحداث بعد الـ commit بلا بريد ولا رمز.

## 4. ما ينقص

- **الواجهة**: لا شاشة لإدارة الأعضاء والأدوار والدعوات، ولا صفحة قبول دعوة (`/invite?token=`). يحتاج `i18n` عربي/إنجليزي وحالات تحميل/فراغ/خطأ.
- **Idempotency-Key** على إنشاء الدعوة: القاعدة تطلبه للسجلات المالية والمخزنية، والدعوة ليست منها، فلم يُطلب. التكرار محمي بالفهرس الفريد (409 `invitation_pending`). قرارك إن أردت المفتاح.
- **إرسال البريد**: خارج النطاق حتى اختيار مزوّد.
- **الحد من المحاولات** على مسار القبول (rate limit): غير موجود، والرمز 256 بت لذلك التخمين غير عملي، لكن يُنصح به عند النشر.
- **دور `inventory_manager`** وأي دور إداري افتراضي آخر: لم يُنشأ (قرار مفتوح).
